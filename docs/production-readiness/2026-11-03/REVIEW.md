# ikea3dbuilder review

## Scope and verdict

Static review of prototype `c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42`. Sampled files: `README.md`, `tools/server.py`, `tools/test_chrome.py`, plus snapshot inventory metadata. Runtime, browser/device checks, installs, renderer execution, and tests were **not run**. The sampled repo does show a real local authoring server with reachable static security defects, but it does **not** prove the README's mechanical-fidelity, rendering-fidelity, or assembly-guidance claims.

## Architecture and product boundary

The inventory contains a static viewer (`index.html`, `viewer/`), local authoring/server tooling, a Python pipeline, product JSON/manual assets, and vendored Three.js/fonts. The observed authoring entrypoint is [tools/server.py:3-8](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L3-L8), which states it will ["serve[] the project root and accept[] writes to products/*/build.json"](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L5-L6). The sampled smoke script is separate tooling, not the viewer runtime: [tools/test_chrome.py:1-5](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/test_chrome.py#L1-L5) imports `websockets` and opens a local Chrome debugging tab.

Source-grounded boundary from the sampled files:
- **Prototype/runtime boundary:** README product claims such as ["physically accurate, page-by-page 3D builds"](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/README.md#L3-L5) and ["1:1 mechanical precision"](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/README.md#L5-L5) were not validated against running output, hardware, or manuals.
- **Offline/runtime vs tooling/dependency boundary:** [README:22](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/README.md#L22-L22) says the project ["runs completely offline with zero external dependencies (Three.js and fonts are vendored in `lib/`)"]. That is supportable only as a sampled viewer/runtime claim about vendored browser assets, not a blanket repo-wide tooling claim, because `tools/test_chrome.py` separately imports `websockets` and depends on a local Chrome debugging endpoint.
- **Persistence boundary:** the sampled mutable state is local overwrite of `products/*/build.json` through `/api/save`; no database, cloud storage, or sync service was sampled.
- **Privacy boundary:** the sampled data surface is local product/catalogue JSON plus API request logging. [tools/server.py:35-36](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L35-L36) logs `self.address_string()` for `/api/` calls. No telemetry SDK, cookie banner, browser storage implementation, or remote analytics path was personally inspected, so privacy/offline assurances should not be expanded beyond these sampled surfaces.

## Findings ledger

- **IB-1 — High, confirmed static:** [tools/server.py:86-105](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L86-L105) handles `"/api/save"` and finishes with `"os.replace(tmp, dest)"`; [tools/server.py:129-130](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L129-L130) binds `"find_server(\"0.0.0.0\", PORT)"`. There is no sampled authn/authz check around that write path, so any reachable network client can overwrite selected `products/*/build.json` files. Default to loopback, add explicit authorization for any non-local write mode, and document that dev labeling is not a security boundary.
- **IB-2 — High, confirmed static:** [tools/server.py:74-80](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L74-L80) takes `"slug = (q.get(\"id\") or [\"\"])[0]"` and then computes `"pj = os.path.join(ROOT, \"products\", slug, \"pages.json\")"`. Traversal segments or absolute paths can escape the intended product directory and expose another readable `pages.json`. Validate one slug format and verify the resolved target remains under the product root, including symlink cases.
- **IB-3 — Medium, confirmed static:** [tools/server.py:29-32](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L29-L32) sends `"Access-Control-Allow-Origin", "*"`; [tools/server.py:87-89](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L87-L89) trusts `"Content-Length"` and reads `"self.rfile.read(n)"` without an explicit cap. Combined with IB-1, this weakens origin boundaries and leaves resource-consumption behavior undefined. Add size limits plus Origin/Host policy matched to the intended local-only or authenticated deployment model.
- **IB-4 — Medium, unverified risk:** [README:3-5](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/README.md#L3-L5) promises `"physically accurate, page-by-page 3D builds"` and `"1:1 mechanical precision"`; [README:9-16](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/README.md#L9-L16) advertises `"Featured Builds (10/10 Fidelity)"`. No sampled source proves mechanical fidelity, safe assembly sequencing, or manual-step correctness. Keep prototype/rendering/geometry claims clearly illustrative until each product is independently checked against authorized manuals and physical examples.
- **IB-5 — Low, confirmed static:** [tools/server.py:60-72](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/server.py#L60-L72) returns `"{\"products\": items, \"root\": ROOT}"`, disclosing the server's absolute local root path in catalogue responses. Remove that field unless an approved local-only diagnostic requirement justifies it.

## Five-discipline assessment

**Code/correctness:** IB-1, IB-2, and IB-5 are direct static defects in the sampled HTTP handler. Thread behavior, symlink handling beyond the visible join, and actual viewer/manual correctness remain unverified because runtime was not exercised.

**Automation/testing:** [tools/test_chrome.py:57-80](https://github.com/knarayanareddy/ikea3dbuilder/blob/c9bc24e83ceaebb41c24032a1dbaaf2560c2dc42/tools/test_chrome.py#L57-L80) only waits for boot and reports `"ALL 4 KITS TESTED CLEANLY WITH ZERO EXCEPTIONS!"`. That is a smoke/exception check, not evidence of rendering fidelity, browser compatibility, accessibility, or manual-step correctness. No sampled CI workflow was inspected.

**DevOps/operations:** the sampled persistence surface is local file mutation of `products/*/build.json`, with a fixed `dest + ".tmp"` intermediate path. Backup/restore, concurrent editing policy, release packaging, and recovery evidence were not sampled. The server also exposes its filesystem root in catalogue output.

**Security/OWASP and data protection:** the sampled handler lacks visible authn/authz around write operations, accepts traversal-influenced read input, sends wildcard CORS, and logs API client addresses to stderr. The sampled privacy surface is therefore limited but real: local product/catalogue JSON plus request logging. No sampled evidence supports broader privacy promises such as “no logging anywhere,” “no browser storage,” or “no telemetry” across the whole repo.

**UI/UX/accessibility:** the viewer/manual pairing is a real user-facing surface, but keyboard support, screen-reader behavior, reduced-motion handling, text alternatives, fallback states, and device/browser behavior were not run. Prototype/runtime/rendering/geometry limits must stay explicit.

## Owner decisions and blockers

Determine whether authoring is strictly local-only or allowed over a network, who may edit product JSON, what retention applies to API request logs, which manuals/images may be redistributed, and whether the viewer is illustrative or intended as assembly guidance. Any external deployment also needs an owner decision on dependency/update policy for vendored browser assets versus auxiliary tooling such as the Chrome-debug smoke script. Do not represent this prototype sample as product safety certification.

## Evidence and limitations

Inspected `README.md` 1-127, `tools/server.py` 1-142, and `tools/test_chrome.py` 1-84 from the pinned snapshot, plus tree inventory metadata. The sampled persistence/privacy discussion above is limited to visible file writes and request logging in these three files; it is not a whole-repo privacy certification.
